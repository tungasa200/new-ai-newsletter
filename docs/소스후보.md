# 수집 소스 후보 (P-1, P-2 개정)

- 확인 날짜: 2026-11-11. 피드 동작은 사용자 PC의 가정용 회선에서 `curl -L`로 직접 받아 확인했다.
- P-2(2026-11-11)에서 A 등급 소스의 robots.txt와 이용약관을 확인해 "수집 허용"·"근거" 칸을 넣었다. B·X 등급은 확인하지 않았다(`—`). B 등급을 추가할 때 같은 방식으로 확인한다.
- **주의**: 클라우드 IP(GitHub Actions 등)에서는 결과가 다를 수 있다. 다시 확인할 목록은 6절에 있다.
- **주의**: HTTP 200이 "살아 있는 피드"라는 뜻은 아니다. 갱신이 멈춘 피드(OpenAI developers)와 날짜가 틀린 피드(TLDR AI)가 있다. 수집기는 소스마다 마지막 새 항목 날짜를 기록하고, 오래 멈추면 알린다(FR-OPS-07).
- 범주: **A** = 1차 도입(D-08 확정), **B** = 2주 운영 뒤 추가 후보, **X** = 제외.
- 수집 허용 판정:
  - **허용**: robots.txt와 약관에 걸리는 조항이 없다.
  - **조건부**: 적힌 조건을 지키면 쓴다.
  - **금지**: robots.txt나 약관이 막는다. 이 수집 방법은 쓰지 않는다.
  - **미확인**: 약관 원문을 열지 못했다.
  - 약관 판정은 법률 자문이 아니라 문구를 읽고 한 판단이다.

## 4. 공통 수집 원칙

- 본문을 통째로 옮기지 않는다. **자기 문장으로 쓴 요약 2–3문장과 원문 링크만** 싣는다. 원문 문장을 그대로 번역해 싣는 것도 하지 않는다(2차적저작물 위험). 이미지는 싣지 않는다.
- 피드·API가 있으면 HTML보다 먼저 쓴다. 약관이 스크래핑을 막는 사이트도 스스로 내놓은 피드를 읽는 것은 위험이 낮다.
- robots.txt를 지킨다. 실행할 때 robots.txt를 읽어 확인하는 것은 HTML 수집 대상에만 하면 된다.
- 정직한 User-Agent(서비스 이름과 저장소 URL)를 쓰고, 하루 1회만 수집하며, 소스마다 요청 1–3회로 제한한다.
- 수집한 본문 발췌는 실행 중에만 쓰고, 상태 저장소(D-03)에는 URL·제목·날짜만 남긴다.
- 1차 도입(A) 기준 소스는 약 17개다. 하루 수집량은 중복을 빼기 전 50–150건으로 추정한다(레거시 실행 로그가 없어 실측값은 아니다).
