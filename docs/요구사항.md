# 요구사항 (초안, P-1)

- 상태: 초안. 결정 D-01~D-11 확정(2026-11-11) 반영. 결정 후보는 `docs/결정기록.md`, 호스팅 비교는 `docs/호스팅비교.md`, 소스 후보는 `docs/소스후보.md`.
- 작성: AN-planner, 2026-11-11

## 1. 목적

AI 관련 소식을 공식 소스(벤더 블로그·릴리스 노트·changelog)와 커뮤니티에서 모은다. Claude가 선별·중요도·신선도를 판단하고 편집해서, **실무에 바로 적용할 수 있는 기능·사용팁** 위주의 한국어 뉴스레터를 매일 아침 지정 메일로 보낸다.

핵심 가치는 실무 적용성과 **신선도**다. 모델과 도구가 몇 달 단위로 바뀌므로 "몇 달 전엔 최신이었지만 지금은 대체된 기법"을 걸러야 한다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 항목(item) | 수집한 글 하나(블로그 글, 릴리스 노트 한 건, HN 글, Reddit 글 등) |
| 공식 소스 | 벤더가 직접 내는 블로그·릴리스 노트·changelog·GitHub releases |
| 커뮤니티 소스 | HN, Reddit, 실무자 블로그, GitHub 트렌딩 등 제3자 글 |
| 실무팁 | 독자가 오늘 바로 따라 할 수 있는 구체적 사용법(설정·명령·프롬프트·워크플로) |
| 신선도 | 그 내용이 **지금도** 권장되는 방법인지에 대한 판단(발행일과는 다름) |
| 발송 이력 | 이미 메일에 실은 항목의 정규화 URL·제목 해시 목록 |

## 3. 기능 요구사항

ID 체계: `FR-<영역>-<번호>`. 영역 = SRC(수집), SEL(선별·판단), DUP(중복·신선도), EDT(편집), MAIL(발송), RCP(수신자), OPS(실패·운영). 우선순위 M(필수)/S(있으면 좋음)/C(나중).

## 4. 비기능 요구사항

| ID | 요구사항 | 기준(결정 D-07 등) |
|---|---|---|
| NFR-01 비용 | Claude API 하루 비용 상한 | 상한 **$1.00/일**(월 약 $30, D-07 확정). "하루"는 같은 KST 날짜에 돈 실행들의 합산이다(D-10). 실행 중 누적 토큰으로 비용을 추정해 상한의 80%($0.80)에 이르면 편집·메모 갱신 단계의 입력 항목 수를 줄이고, $1.00을 넘을 것 같으면 메모 갱신 단계를 건너뛴다. 예상 평균은 $0.15–0.25/일(결정기록 D-06) |
| NFR-02 비용 | 호스팅·메일 비용 | 월 $0–5. 무료 한도 안을 우선 |
| NFR-03 실행 시간 | 한 번 실행의 전체 시간 | 목표 5분 이내, 상한 15분. 호스팅의 실행 시간 제한이 이보다 짧으면 안 된다 |
| NFR-04 신뢰성 | 발송 성공률 | 월 기준 하루도 빠짐없이 발송(실패 시 같은 날 재시도로 회복). 실패는 당일 운영자가 안다 |
| NFR-05 운영 부담 | 사람 손 | 평소 0분. 소스 추가·수신자 변경은 설정 한 곳만 고친다. 월 1회 이하 점검 |
| NFR-06 보안 | 비밀값 | API 키·메일 비밀번호·수신자 주소는 호스팅 비밀값에만 둔다. 로그·메일·저장소에 남기지 않는다 |
| NFR-07 이식성 | 호스팅 종속 | 핵심 로직은 "명령 한 줄로 실행되는 배치"로 만든다. 호스팅을 바꿔도 스케줄 설정과 상태 저장 어댑터만 바꾼다 |
| NFR-08 테스트 | 검증 | 소스 파서는 저장된 샘플(fixture)로 단위 테스트. Claude·메일은 가짜(mock)로 흐름 테스트. 실제 호출은 `--dry-run`으로 수동 확인 |

## 5. 레거시(newsletter-lgcy)에서 유지할 것과 바꿀 것

레거시 실제 구성(`main.py` 확인, README의 "RSS 12개"보다 넓다): 매체 RSS 11개 + 실무 블로그 RSS 5개 + HN(Algolia) + Reddit 3개 서브레딧(비인증 JSON) + arXiv + GitHub Search → Claude(`claude-sonnet-4-6`) 1회 호출로 선별·요약·분류 → Python이 신문형 HTML 렌더링 → Gmail SMTP(465) → GitHub Actions cron `0 22 * * *`(07:00 KST).

| 영역 | 레거시 | 유지/변경 | 새 방향 |
|---|---|---|---|
| 언어 | Python 3.11, feedparser·requests·anthropic | 유지(제안) | Python 3.12+. 레거시 수집 코드를 재사용할 수 있다 |
| 소스 구성 | 매체 기사 중심(TechCrunch·Verge·Wired 등) + 실무 블로그 | **변경** | 공식 벤더 changelog·릴리스 노트·GitHub releases를 중심에 두고, 일반 매체는 줄인다(실무 적용성 기준) |
| 소스 목록 위치 | 코드 안 딕셔너리 | 변경 | 설정 파일(FR-SRC-03) |
