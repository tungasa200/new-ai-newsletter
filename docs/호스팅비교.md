# 호스팅·스케줄 비교 (P-1)

- 확인 날짜: 2026-11-11. 가격·한도는 아래 공식 문서에서 확인했다. 공식 페이지에서 확인하지 못한 항목은 **미확인**으로 표시했다.
- 작업 성격: 하루 1회(07:00 KST), 3–10분 배치. 소스 20–30개 수집, Claude API 호출 2–3회(호출당 30–120초), 메일 1통. 비밀값 4–5개, 작은 상태 저장소(발송 이력, 수 KB–수 MB)가 필요하다.

### 그 밖의 후보(간단히)

- **Render Cron Job**: 초 단위 과금이고 서비스당 월 최소 $1, 실행당 최대 12시간이다. 영구 디스크를 쓸 수 없어 상태는 외부에 둬야 한다[O1]. Railway와 비슷한 위치라 따로 고를 이유가 적다.
- **Google Cloud Run Jobs + Cloud Scheduler**: 무료 사용량이 넉넉하지만[O2] Jobs에도 무료 사용량이 적용되는지, Scheduler 무료 job 수는 몇 개인지 확인하지 못했다. 그리고 GCP 결제 계정·IAM 설정이 필요해 운영 부담이 가장 크다.
- **집 PC 작업 스케줄러**: PC가 꺼져 있으면 발송되지 않아 NFR-04(빠짐없는 발송)를 만족하지 못한다. 제외.

## 2. "GitHub Actions에 비용이 추가로 든다"는 걱정에 대해

- 이 작업 규모에서는 비용이 들지 않는다. 비공개 저장소의 Free 계정 포함분은 월 $12 상당이다(Linux 2-core $0.006/분 기준 약 2,000분)[G1]. 이 작업은 하루 5분 × 31일 + 재시도 실행을 합쳐도 월 300분이 안 되므로 포함분의 15% 이하다.
- 2026-01-01부터 hosted runner 가격은 최대 39% 내렸고 무료 분량은 그대로다. self-hosted runner 요금($0.002/분)은 시행이 **연기**됐고, 이 작업은 GitHub이 제공하는 hosted runner를 쓰므로 해당하지 않는다[G6].
- 비용이 드는 경우는 포함분을 넘겼을 때뿐이다(다른 저장소의 CI가 포함분을 함께 쓰는 경우 등). 이때도 지출 한도를 $0으로 두면 과금되지 않고 작업만 멈춘다(지출 한도의 기본값이 몇인지는 미확인이라 설정 화면에서 확인할 것).

## 3. 추천안: GitHub Actions(비공개 저장소)

이유:
1. **비용 $0**이고, 레거시에서 이미 동작이 검증된 경로다(확실하게 동작하는 것이 우선이라는 요구에 맞는다).
2. 실행 시간 제한(6시간)이 넉넉해서 Claude 호출이 길어져도 안전하다. Vercel은 300초에서 잘린다.
3. 실패 알림, 수동 실행(`workflow_dispatch`), 비밀값 관리, 실행 로그가 모두 기본으로 들어 있어 따로 만들 운영 기능이 가장 적다.
4. 상태(발송 이력)를 같은 저장소의 `state` 가지에 JSON으로 커밋하면 외부 DB가 필요 없다. 사람이 이력을 열어 보고 고치기도 쉽다.

약점과 대응:
- 스케줄이 지연되거나 드롭될 수 있다[G2]. 그래서 cron을 **두 번** 건다(예: 06:30 KST, 07:30 KST). 두 번째 실행은 오늘 이미 발송했으면 바로 끝낸다(FR-MAIL-04 이중 발송 방지). 지연은 몇 분에서 수십 분 수준이라 "07:00 ± 30분" 목표를 대체로 지킨다.
- 공개 저장소로 바꾸면 60일 동안 활동이 없을 때 스케줄이 꺼진다[G2]. 그래서 비공개 저장소로 둔다. 비공개 저장소에 이 비활성화 규칙이 적용되지 않는다는 점은 문서 문구("public repositories")에 따른 해석이다.
- 실패 알림은 받는 사람이 Actions 알림을 켜 둬야 받는다[G4]. 앱이 운영자 메일로 직접 알리는 기능(FR-OPS-03)도 함께 둔다.

호스팅을 나중에 바꿔도 되도록 핵심 로직은 `python -m ainews run` 같은 명령 한 줄로 실행되게 만든다(NFR-07). 그러면 Railway로 옮길 때 cron 설정과 상태 저장 방식만 바꾸면 된다.
